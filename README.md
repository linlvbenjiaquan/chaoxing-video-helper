# 学习通网页版视频挂机器

一个 Tampermonkey（油猴）用户脚本：在学习通（超星）网页课程页里，**按目录顺序自动播放课时视频**——一节播完自动进下一节，直到做完。

它不碰鼠标坐标、也不模拟点击屏幕，而是直接操作页面里的目录节点，目录折叠、页面滚动、换分辨率都不影响它干活。

---

## 能做什么

- **按顺序自动播**：从目录里第一节"未完成"的课时开始，点开 → 把视频播起来 → 播完**立刻**进下一节（监听播放器的 `ended` 事件，切到后台也能准点跳）。
- **自动跳过分组标题**：靠页面结构区分「课时行」和「分组标题行」，永远不会误点到「1 国防概述」这种标题导致目录折叠错位。
- **跳过已刷完的**（可选项）：目录里带"已完成"绿标的那几节直接跳过，从没做完的那节接着刷。
- **卡住保护（看门狗，可开关）**：视频进度连续 2 分钟不往前走，先自动重试播放（最多 2 次），还不动就暂停并用系统通知提醒你。适合挂着睡觉的场景。
- **多标签页互斥**：同时开两个标签页时，只有一个真正干活，另一个待命；干活的那个关掉后会自动接管。
- **系统通知 + 标题闪烁**：需要你处理（如卡住、跑完）时通知你；只在**你没看这个页面**时才闪标题。
- **三种刷新方式**：
  - 整体模式：每节播完整页刷新一次（进度和绿标始终最新，代价是每节多花几秒）
  - 均衡模式（默认）：切节不刷新，全部跑完后自动刷新一次给你验收
  - 局部模式：从不刷新（最快，绿标要自己手动刷新才看得到）
- **播放倍速**：1.0x / 1.25x / 1.5x / 2.0x；课程不允许倍速时脚本会自动放弃，不跟播放器死磕。
- **面板可拖动**，位置会记住；**运行状态存在浏览器本地**，刷新页面/跳转章节能接着跑。
- **结束汇总**：跑完列出总课时、本轮播完多少、跳过了哪些（附原因）。
- 3.1 版还有**后台核对**：每节播完后在后台悄悄重抓一次课程页面（不刷新你眼前的页面），确认平台有没有把这一节记成已完成；没记上的进"可疑清单"。

## 不能做什么

- **不做测验、不交作业、不答题、不参与讨论**——它只处理"视频"这一类任务点。所以如果某一节里还挂着章节测验，**那一节在平台上不会变成"已完成"**。
- **不伪造进度、不直接往服务器提交任何数据**。它做的事等价于"你本人坐在那里点下一节、按播放"，走的是平台本来就有的正常播放上报流程。
- **不破解、不绕过任何验证**：遇到验证码、人脸核验这类东西不会去硬闯，脚本会停下来提醒你处理。
- **不保证适配所有课程和所有页面版本**：目录选择器是针对超星 `#coursetree` 这套页面结构写的，平台改版后可能失效（失效时脚本会提示"目录里没读到课时行"）。
- **不是多账号工具**：没有批量、没有代刷、没有共享登录之类的功能。

## 安装（手把手版）

### 第 0 步：用哪个浏览器

**Edge** 或 **Chrome** 都可以（两个都是 Chromium 内核，操作几乎一样，下面两条路都会写）。用 Edge 打开学习通也完全没问题，脚本在 Edge 里一样生效。

### 第 1 步：装用户脚本管理器（Tampermonkey，中文叫"篡改猴"）

**用 Edge：**

1. 打开 Edge，地址栏输入 `edge://extensions` 回车；把**左下角的「开发人员模式」打开**（先别关这个页面）。
2. 地址栏输入 `microsoftedge.microsoft.com/addons` 回车，搜索框搜 **Tampermonkey**，找到那个猴子图标的扩展 → 点「获取」→ 弹窗里点「添加扩展」。

**用 Chrome：**

1. 打开 Chrome，地址栏输入 `chrome://extensions` 回车；把**右上角的「开发者模式」打开**。
2. 打开 `chromewebstore.google.com`，搜索 **Tampermonkey** → 「添加至 Chrome」→「添加扩展程序」。

**懒人版**：也可以直接打开 [tampermonkey.net](https://www.tampermonkey.net/) → 点「下载」→ 点你浏览器的图标 → 会自动跳到对应商店安装。

### 第 2 步：打开"允许用户脚本"（**最容易漏，漏了脚本就不跑**）

新版 Chrome / Edge 出于安全考虑，装完扩展还**必须手动允许用户脚本**，否则 Tampermonkey 装了也不干活：

1. 回到 `edge://extensions` 或 `chrome://extensions`；
2. 找到 **Tampermonkey**，点它下面的「**详细信息**」；
3. 在详细信息页里找到「**允许用户脚本 / Allow user scripts**」——**打开它**；
4. 顺便看一下同一页的「**网站访问权限**」（有的版本写成"允许此扩展读取和更改您在所有网站上的数据"），把它设成「**在所有网站上**」。设成"点击时"的话，脚本同样不会自动运行。

> 如果这两项没开，Tampermonkey 的菜单里会冒出一段**红色警告**，点开它也会告诉你该去哪里打开。

### 第 3 步：把猴子图标固定到工具栏

点地址栏右边那个「拼图 / 扩展」图标 → 找到 **Tampermonkey** → 点它右边的图钉，让它常驻工具栏（以后看面板、查日志都靠它）。

### 第 4 步：装脚本

两种方式任选一种：

- **拖进去（最快）**：把下载到的 `学习通网页版视频挂机器-vX.X.user.js` 文件，从文件夹里**直接拖到浏览器窗口中间** → 会弹出一个 Tampermonkey 的安装页面（能看到脚本名和前面一段代码）→ 点「**安装**」。
- **复制粘贴**：点工具栏上的 Tampermonkey 图标 → 选「**添加新脚本**」→ 在编辑框里按 `Ctrl+A` 全选、`Delete` 清空模板 → 把脚本内容整段粘进去 → 按 `Ctrl+S` 保存。

> 如果同时装了多个版本的同一脚本，记得**只留一个**——多余的会互相抢着切下一节。

### 第 5 步：确认装好了

1. 打开学习通的课程章节页面（就是有「目录 / 讨论 / 笔记 / 标注」那一页）；
2. 按 **`Ctrl+R` 刷新一次**（脚本只在页面加载时启动，装完必须刷新；用 Ctrl+R 就行，不用去按 F5）；
3. 页面**顶部会闪一条提示**、**右下角出现控制面板** → 成功。

**没反应的话，按顺序排查：**

- 油猴里这个脚本的开关是不是**绿色（已启用）**；
- 第 2 步的「允许用户脚本」和「网站访问权限」是不是都开了；
- 拖进去时弹出的安装页面是不是还没点「安装」；
- 想看得更清楚：按 `Ctrl+Shift+J` 打开控制台，看有没有 `[挂机器]` 开头的日志——**有**说明脚本已经在跑了，**没有**说明脚本没被注入，回到上面两项检查。

## 使用

面板上的东西：

| 控件 | 说明 |
| --- | --- |
| 开始 / 暂停 | 开始或暂停自动播放（暂停后视频不再被自动播放） |
| 跳过这一节 | 立刻放弃当前节，进下一节 |
| 清空本轮记录 | 清掉"本轮已播完"的记录（带确认框），清空后会重新处理所有课时 |
| 跳过已刷完的课时 | 目录里有绿标的直接跳过；关掉就是全部重刷一遍 |
| 卡住保护（看门狗） | 见上文 |
| 刷新方式 | 整体 / 均衡 / 局部，见上文 |
| 播放倍速 | 见上文 |
| 单节最多等 N 分钟 | 超过这个时间视频还没播完就当卡住，跳过（默认 45 分钟） |
| 每节结束后后台核对（3.1） | 见上文；面板上还有「立即核对一次」按钮可以立刻试 |
| 收起 / 拖动 | 点标题栏右边的「收起」折叠面板；**按住标题栏可以拖动整个面板**，位置会被记住 |

## 常见问题

**没看到面板？** 脚本是在页面加载时执行的，装完必须刷新页面；再确认油猴里这个脚本是启用状态（开关是绿色）。

**一下出现好几个面板？** 那是旧版本（1.2 之前）的问题，后来加了 `@noframes` 只在最外层窗口运行。如果你装了好几个同名脚本，删到只剩一个。

**目录里的绿标不更新？** 目录是页面加载时渲染的，不刷新就不会变——所以脚本**不依赖**绿标判断"播完了"，而是直接听播放器的结束事件。

**会不会很吃性能、让电脑卡？** 不会。脚本每 2 秒动一次，CPU 占用大约 0.3%；后台核对是每节课才做一次。真正吃资源的是视频解码和超星页面本身。

**提示"没找到 video 元素"？** 播放器在跨域 iframe 里，脚本读不到视频进度，会退化成靠"目录完成标记"判断；这种情况下建议用 3.1 的后台核对来确认进度。

**想退回旧版本？** 用仓库里对应版本的 `.user.js` 覆盖安装即可（3.1 里把「后台核对」的勾去掉，行为基本等于 3.0）。

## 已知不足与未完成的部分

如实写下来，免得后来的人踩同样的坑。

### 1. 多任务点章节的徽标"1"分不出是哪一项没做（**未解决**）

超星目录里每节徽标的含义——它是"**还剩几个任务点**"：

| 徽标 | 含义 |
| --- | --- |
| 绿色勾 | 全部任务点都完成 |
| `1` | 还剩 1 个（两项里做完了其中一项） |
| `2` | 还剩 2 个（一项都没做） |

问题就出在 `1`：**它不告诉你"做完的是视频还是测验"**。这两种完全不同的状态，目录里都显示 `1`：

- 看了视频、没做题；
- 做了题、没看视频。

**影响**：脚本的策略是"只要不是绿勾，就把视频播一遍"，所以

- 两种情况都不会出错（该播的一定会播到完）；
- 但"视频其实已经看过"的那种，会**白白重看一遍**（一节可能十几分钟）；
- 同一台电脑/同一个浏览器会记住"本轮播过哪些节"，所以在一台机器上只会白看这一次；**换浏览器、清缓存、换账号之后再跑，就会重看**。

**为什么没做完**：要解决它，需要各拿一节"视频已看完（徽标 1）"和"视频没看过"的页面做字段对照，才能确定超星是把观看进度写在哪个字段里——而**作者自己的学习通课程已经全部刷完了**，手上没有"未完成的课程"能做这个对照实验，所以停在了半路。**思路和勘察办法都写在下面了，欢迎后来者接手。**

### 2. 本机记录不区分账号

"本轮播过哪些节"存在浏览器本地（localStorage），而它是**按站点存、不按账号分**的。

**影响**：在同一台电脑、同一个浏览器里换了账号之后，章节 ID 是一样的，脚本会以为"这些节我做过了" → **直接跳过、整段漏刷**。帮别人刷课时特别容易撞上。

**临时办法**

- 每次换账号后，先点一下面板上的「清空本轮记录」（带确认框）；
- 或者干脆一个账号用一个浏览器 / 一份浏览器用户配置。

**正式修法**（不难，留给后来者）：页面里有隐藏字段 `#uploadUid`（用户标识），URL 里还有 `cpi`。用它们当存储键，把「运行记录」按账号分开存，而「设置项」（刷新方式、倍速、面板位置）继续共用即可。

### 3. 其它已知边界

- **带测验的章节永远不会变成绿勾**（脚本按设计不碰测验），所以"已完成"的节数和绿勾数量对不上是正常的；
- **依赖超星的页面结构**：目录相关选择器写的是 `#coursetree` 里的 `posCatalog_select / posCatalog_name / icon_Completed` 这些类名，平台改版后可能失效（失效时脚本会提示"目录里没读到课时行"）；
- **读不到视频时会退化成靠目录标记判断**：如果播放器在跨域 iframe 里，脚本拿不到 `video` 元素，就只能靠"目录里的完成标记 + 超时"来推进；
- **3.1 的「后台核对平台进度」尚未在真实课程上验证过**（作者没有可用的未完成课程来测；如果它抓回来的页面里没有目录行，脚本会自动关掉这个功能，不影响刷课）；
- 没有多课程排队、批量账号之类的功能（也不打算做）。

## 给后来者的思路（想把上面第 1 条做完的话）

"这一节的视频到底看完没有"，有三条路，成本从低到高：

**① 打开后 3 秒探测（成本几乎为零）**
点开一节后读一次 `video.currentTime`：如果已经 ≥ 时长 − 15 秒，就说明这视频本来就播到过结尾 → 直接进下一节。
前提是超星的播放器会"从上次位置续播"——这一点已经验证过，确实如此。

**② 读章节页里的进度字段（最准，推荐）**
既然播放器能续播，就说明服务端把观看进度写进了章节页的 HTML。那么用 `fetch(location.href)`（同源、带自己的登录态）把那一节的页面拉下来、用 `DOMParser` 离线解析，去找里面表示"看了多少"的字段（大概率是 `viewTime` / `playingTime` / `totalTime` 这类），就能**在点开之前**判断这节的视频有没有看完，连页面都不用加载。

勘察办法：站在那一节的页面上打开控制台，把章节页 HTML 里跟 `viewTime|playingTime|totalTime|duration|complete|progress` 这些关键词有关的行筛出来打印，再拿一节"视频没看过"的页面做同样的打印，**两边不一致的字段就是你要找的东西**。

**③ 读平台的任务点接口**
最持久但最麻烦，需要在开发者工具的「网络」面板里抓请求、看返回的 JSON。上面两条搞不定再考虑。

另外建议顺手把「已知不足 2」一起修掉：**用 `#uploadUid` 或 URL 里的 `cpi` 把运行记录按账号隔离**，几行改动的事。

## 作者的话

这个脚本是冲着"网课视频任务点"这种枯燥活儿写的：能自动一节一节把视频播完，挂着就不用管了。自己用已经完全够用。

之所以停在现在这个状态，是因为我的学习通课程已经全部刷完了，手上没有"未完成的课程"可做对照实验（上面第 1 条那个字段比对必须两种状态各来一节才行），所以明知道往下怎么做，却没有数据能验证。作者本人也并非计算机专业学生，对于Python并不精通，本作品是由接入DeepSeek V4.1 Flash的Codex完成的。

所以把它放到这里，希望后来者能在这个基础上继续完善——尤其是上面那两条已知不足。代码不长、结构也简单（目录解析 / 视频探测 / 控制面板三块），改起来不难。
